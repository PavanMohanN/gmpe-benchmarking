# gmpe-bench

**A leakage-free benchmark and calibrated-uncertainty toolkit for ground-motion models on NGA-West2.**

`gmpe-bench` turns the NGA-West2 flatfiles into an ML-ready dataset, freezes
grouped benchmark splits with an automatic leakage audit, evaluates classical
NGA-West2 GMMs and machine-learning models on the same folds, and calibrates
their uncertainty with **HSCP** (Hierarchical Spectral Conformal Prediction).
Every number, table and figure in the accompanying paper is regenerated by the
commands below, and each stage writes a SHA-256 manifest.

- Python 3.10–3.12 · Windows, macOS, Linux
- One command-line tool, `gmpe-bench`, plus one script per pipeline stage
- No data are redistributed: you download the flatfiles from PEER

## Installation

```bash
git clone <repository-url> gmpe-bench
cd gmpe-bench
python -m venv .venv
# Windows: .venv\Scripts\activate      macOS/Linux: source .venv/bin/activate
pip install -e .
gmpe-bench selftest
```

Core dependencies (installed by `pip install -e .`, see `pyproject.toml`):
numpy, pandas, pyarrow, openpyxl, scipy, scikit-learn, matplotlib, typer.

Model-specific dependencies:

| Stage | Package | Used for |
| --- | --- | --- |
| Classical baselines | `pygmm` (tested with 0.8.0) | ASK14, BSSA14, CB14, CY14 |
| ML models | `xgboost` (≥ 2.0) | XGBoost spectral GMM |
| ML models | `torch` (CPU or CUDA) | Spectral MLP and hybrid models |
| Tests | `pytest`, `Pillow` | Test suite |

A CUDA GPU is used automatically when available; everything also runs on CPU.

### Check the installation

```bash
gmpe-bench selftest
```

`selftest` checks Python, the core dependencies and write access, then runs an
**installation smoke test**: a tiny synthetic fixture held in memory goes through
the split leakage audit, a model fit and the event-clustered and HSCP
calibrators. It needs no PEER files and takes a few seconds. Its output is
clearly bannered and is **not NGA-West2 benchmark output**; do not report it.
Use `gmpe-bench selftest --no-smoke` to run the environment checks only.

## Data

Every benchmark number comes from the real NGA-West2 data, which PEER does not
allow us to redistribute. You build the curated profile once on your machine:

1. Open the PEER ground-motion database (<https://peer.berkeley.edu>) and
   download the NGA-West2 flatfiles: the **horizontal (RotD50)** flatfile and the
   **vertical** flatfile (January 2015 update).
2. Save them in the repository root as:

   ```
   nga_w_h.xlsx    # horizontal flatfile
   nga_w_v.xlsx    # vertical flatfile
   ```

   CSV versions are also accepted. The build step checks every required column
   and fails with a clear message if one is missing.
3. Build the curated profiles (rules R1–R12):

   ```bash
   gmpe-bench build --h nga_w_h.xlsx --v nga_w_v.xlsx
   ```

   This writes `data/processed/full.parquet` (20,926 records, 575 earthquakes,
   4,026 stations) and `sp23.parquet`.
4. Keep the frozen splits that ship with the repository
   (`data/processed/splits_full.json`, `splits_sp23.json`). They are stored by
   record sequence number and tied to the profile by a SHA-256 fingerprint, so
   every user evaluates on identical folds. Do not run `gmpe-bench split` unless
   you deliberately want new splits.

## Benchmark your own model (Python API)

Five lines, on the curated NGA-West2 profile built above:

```python
import gmpe_bench as gb

class MyGMM(gb.BaseGMM):
    def fit(self, X_train, y_train, metadata_train): ...; return self
    def predict(self, X_test, metadata_test): return mu, sigma      # (n, 27) each, ln units

report = gb.evaluate(MyGMM(), profile="full")
print(report.summary()); report.save("results/my_gmm")
```

`gb.LinearGMM` is a complete reference implementation of `BaseGMM` to copy from.

**The model interface.** `fit` receives the Tier-B inputs of the train-fit rows
(`X_train`, a DataFrame that may contain NaN), the ln targets `y_train` with shape
(n, 27) in `gb.IM_NAMES` order (NaN where a period is unusable), and
`metadata_train` (`rsn`, `eqid`, `ssn`, `region`, `year`, `cl_class`, hypocentre
and station coordinates), so station or event terms can be learned. `predict`
returns `(mu, sigma)` or `mu` alone. Without `sigma`, the class attribute
`default_sigma` is used if set, otherwise the per-IM standard deviation of the
model's own train-fit residuals.

**What `evaluate()` does.** It runs only on `data/processed/full.parquet` or
`sp23.parquet` (or `data_dir=...`, or the `GMPE_BENCH_DATA` variable) and never
on synthetic data. If the profile is missing it stops with the setup steps
above. In every fold of every regime it:

- checks the profile against the frozen split fingerprint and runs the leakage
  audit before fitting (a failing fold raises `gb.LeakageError`);
- refits a fresh copy of your model on train-fit rows only (calibration and
  test targets never reach it);
- scores test RMSE and Gaussian coverage, and calibrates intervals with
  event-clustered conformal prediction and HSCP;
- attaches event-clustered bootstrap 95 % intervals (`n_boot=200` by default)
  and the stored paper benchmarks for `ASK14 (site)` and `Hybrid BSSA14+XGB`
  from `results/paper/paper_summary_numbers.json`.

```python
report = gb.evaluate(MyGMM(), profile="full",
                     schemes=["event_grouped", "spatial_block", "random"],  # default: six leakage-free regimes
                     calibrate=True, n_boot=200)
report.accuracy        # per regime: RMSE, 95 % CI, paper references
report.calibration     # per regime and method: coverage, CI, width, HSCP joint-band coverage
report.to_dataframe()  # one tidy table
report.save("results/my_gmm")  # report.json, CSVs and summary.txt
```

**Models trained elsewhere (PyTorch, JAX, R ...).** `gb.iter_folds()` hands out
every audited fold with train-fit targets only. Return the calibration and test
predictions as a long table (`rsn`, `im`, `mu`, `sigma`, plus `scheme` and
`fold`) and score them with `gb.evaluate_predictions()`:

```python
frames = []
for f in gb.iter_folds("full", ["event_grouped"]):
    net = train_my_network(f.X_train, f.y_train, f.meta_train)      # your code
    frames.append(f.predictions_frame(*net(f.X_cal), *net(f.X_test)))
report = gb.evaluate_predictions(pd.concat(frames), profile="full", calibrate=True)
```

A frame without `scheme` and `fold` columns is read as out-of-fold predictions
of one regime; intervals then use cross-fitted calibration scores, and the
report says so. External training cannot be verified, so reports from
`evaluate_predictions()` record the provenance as declared.

## Interactive explorer app

An optional Streamlit app shows the published benchmark and audits prediction
files. It runs without the PEER flatfiles and without `full.parquet`: it reads
`results/paper/paper_summary_numbers.json` and `results/paper/tables/*.csv`
(or the copies packaged with gmpe-bench).

```bash
pip install -e ".[app]"      # or: pip install "gmpe-bench[app]"
gmpe-bench app               # opens http://localhost:8501
```

| Tab | What it shows |
| --- | --- |
| Benchmark explorer | Leakage inflation (Random vs Event), equal-information RMSE with 95 % event-clustered bootstrap intervals and paired differences, coverage vs width of every calibrator in the six regimes, MACE |
| Period & spectral bands | Per-period RMSE, Gaussian coverage and variance components (τ, φS2S, φ0), calibrated coverage and width per period, HSCP simultaneous whole-spectrum vs marginal coverage, Table S1 |
| Evaluate your predictions | Upload a long-format CSV (`rsn`, `im`, `mu`, `sigma`, optional `scheme`, `fold`); sample template and fold skeleton downloads; schema and frozen-split audit; full `evaluate_predictions()` run when `full.parquet` is present locally |

Options: `gmpe-bench app --port 8502 --host 0.0.0.0 --data path/to/processed --headless`.

**Hosted vs local.** PEER data cannot be redistributed, so a hosted app has no
ground-motion targets. There, an uploaded file is checked against the frozen
splits: the split file's fingerprint, fold disjointness, valid RSNs and IM names,
`sigma > 0`, duplicates, units, train-fit rows, and coverage of each fold's
calibration and test records. The app then shows the code to run the full
evaluation locally. On a machine with the curated profile, the same upload is
scored with `gmpe_bench.evaluate_predictions()` (audited metrics, bootstrap
intervals, HSCP and event-clustered intervals).

### Deploying the app

The repository root holds everything a host needs: `app.py` (entrypoint),
`requirements.txt` (app-only dependencies), `.streamlit/config.toml`
(200 MB upload limit) and a `Dockerfile`. `app.py` imports the package from
`src/`, so hosts do not need the full scientific stack.

- **Streamlit Community Cloud.** At share.streamlit.io choose *Create app*, select
  this repository and branch, set the main file to `app.py` and deploy.
  `requirements.txt` is installed automatically.
- **Hugging Face Spaces.** Hugging Face now runs Streamlit apps through its
  Docker SDK. Create a Space with the *Docker* SDK, push this repository to it,
  and replace the Space's `README.md` with `deploy/huggingface/README.md`. Its
  header sets `sdk: docker` and `app_port: 8501`. The `Dockerfile` builds the
  app; no PEER data are copied (`.dockerignore` excludes flatfiles, parquet and
  pickles).
- **Any container host.** `docker build -t gmpe-bench-app . && docker run -p 8501:8501 gmpe-bench-app`

After a new `gmpe-bench paper` run, refresh the packaged copies with
`python -c "from gmpe_bench.app.data import write_assets; write_assets('.')"`;
`tests/test_app.py` fails if they drift from `results/paper`.

## Quick start

```bash
gmpe-bench build        # Phase 1: clean data      -> data/processed/{full,sp23}.parquet
gmpe-bench split        # Phase 2: frozen splits    -> data/processed/splits_*.json
gmpe-bench baselines    # Phase 3: classical GMMs   -> results/baselines/
gmpe-bench train        # Phase 4: ML models        -> results/ml/
gmpe-bench conformal    # Phase 5: uncertainty      -> results/conformal/
gmpe-bench paper        # Phase 6: tables, figures  -> results/paper/
```

Each command accepts `--help`. The numbered scripts in `scripts/` run the same
stages and print the gate summaries used during development.

## Pipeline and commands

| Phase | Command | Script | What it does |
| --- | --- | --- | --- |
| 0 | `gmpe-bench selftest`, `gmpe-bench info` | — | Check Python, dependencies, write access; show version and paths |
| — | `gmpe-bench app` | `app.py` | Optional Streamlit explorer of the published results and upload audit |
| 1 | `gmpe-bench build` | `scripts/00_build_data.py` | Rules R1–R12: schema mapping, −999 sentinels, H/V join, RotD50 only, usable-period masking at T > 1/LUF, quality flags, CL1/CL2 classes, ln(V/H), ZTOR/Z1.0/Z2.5 fills with flags; profiles `full` and `sp23` |
| 2 | `gmpe-bench split` | `scripts/01_make_splits.py` | Seven split schemes with a 25 % calibration hold-out carved from each training fold; leakage audit (event/station overlap, disjointness, completeness) |
| 3 | `gmpe-bench baselines` | `scripts/02_run_baselines.py` | ASK14, BSSA14, CB14, CY14 via `pygmm` (bias term from `train_fit`) and a crossed mixed-effects GMM; τ, φS2S, φ0 decomposition |
| 4 | `gmpe-bench train` | `scripts/03_train_models.py` | XGBoost, Spectral MLP and physics-residual hybrids for all 27 IMs; predictions for `test` and `cal` |
| 5 | `gmpe-bench conformal` | `scripts/04_run_conformal.py` | Gaussian, split, event-clustered, shift-weighted conformal and HSCP at 90 % and 95 %; conditional and spectrum-wide coverage |
| 6 | `gmpe-bench paper` | `scripts/05_make_paper_artifacts.py` | Paper tables (CSV + booktabs LaTeX), figures (PDF + 800 dpi PNG), captions, manifest |

### Split schemes

| Code | Scheme | Group key | Question |
| --- | --- | --- | --- |
| Rand | `random` | record | Leaky reference: how optimistic is random-split evaluation? |
| Evt | `event_grouped` | EQID | New earthquakes |
| Stn | `station_grouped` | SSN | New sites |
| Reg | `spatial_block` | EQID | New region (leave one hypocentre region out) |
| Temp | `temporal` | EQID | Train before 2008, test 2008 onward |
| Mw≥7 | `magnitude_holdout` | EQID | Large-magnitude extrapolation |
| CL1→2 | `cl1_to_cl2` | EQID | Mainshock-to-aftershock transfer |

### Useful options

```bash
gmpe-bench build --h nga_w_h.xlsx --v nga_w_v.xlsx --profile both

```

The leakage-inflation supplement figure needs results on the random split, kept
apart from the main results:

```bash
gmpe-bench baselines --schemes random --out results/baselines_random
gmpe-bench train     --schemes random --out results/ml_random
```

### Bootstrap confidence intervals

`gmpe-bench paper` computes event-clustered bootstrap intervals (B = 1,000, fixed seed; whole
earthquakes are resampled within each scheme, never individual record-IM pairs) for RMSE, paired
RMSE differences, coverage at 90 % and 95 %, and seen/unseen-station RMSE. Point estimates are the
Table 3 and Table 4 statistics; `paper_manifest.json` (`bootstrap_checks`) records that they are
reproduced. Coverage intervals need per-earthquake counts. A Phase 5 run made before this version
lacks them; add them without refitting any model:

```bash
gmpe-bench conformal --event-counts-only --profiles full   # writes only event_counts.parquet
gmpe-bench paper
```

## Reproducibility

- **Determinism.** Splits, calibration hold-outs, feature pipelines and models are seeded;
  re-running a stage reproduces its outputs (GPU kernels may differ in the last digits).
- **No leakage by construction.** Feature scaling, imputation, station terms, bias terms and
  early stopping use `train_fit` only; `cal` is used only for conformal calibration; test
  labels never enter calibration (`TestInputs` has no target field).
- **Manifests.** `data/processed/manifest.json` (data build), `splits_manifest.json`
  (frozen splits) and `results/paper/paper_manifest.json` (every input read and every
  artifact written) record SHA-256 checksums plus package, Python and platform versions.
  To verify a figure or table, recompute its SHA-256 and compare with the manifest.
- **Caches.** NGA-West2 model evaluations are cached per record and invalidated
  automatically when any input value changes.

## Testing

```bash
pip install pytest pillow
pytest
```

The suite covers the data rules, split disjointness and leakage detection, the
pygmm mapping and units, residual decomposition, the ML pipelines, conformal
coverage guarantees and independence from test labels, the paper artifacts, and
the Python API (`tests/test_api.py`) and the app's loaders and upload audit
(`tests/test_app.py`, headless; the page itself is rendered with Streamlit's
`AppTest` when Streamlit is installed). Tests that need the curated NGA-West2
profile run when `data/processed/full.parquet` exists and are skipped otherwise.

## Manuscript (Earthquake Spectra)

`paper/` holds the manuscript and its electronic supplement in Wiley's NJD LaTeX template
(`USG.cls`, numeric citations as in Wiley's own sample). Tables, figure environments and every
number in the text are read from `results/paper/`, so the PDF always matches the last run.

```bash
gmpe-bench conformal --ablations      # the manuscript reports the four HSCP ablations
gmpe-bench paper                      # tables, figures, numbers.tex, claims_check.csv
cd paper
xelatex main && bibtex main && xelatex main && xelatex main
xelatex supplement && bibtex supplement && xelatex supplement && xelatex supplement
python make_submission.py             # self-contained folder paper/submission/ for upload
```

- **Numbers.** `results/paper/numbers.tex` defines `\GB{key}` for every number in the text.
  Table values are copied as strings from the table cells; figure-only values use the figure's
  own formula. A key the results cannot supply prints `--` and is listed in `numbers_missing.txt`.
- **Claims.** Each directional sentence in `main.tex` carries a claim ID in a comment
  (`% [C07]`). `claims_check.csv` gives PASS / FAIL / NA for each one; rewrite any sentence whose
  claim fails before submission.
- **TeX requirements.** XeLaTeX (Wiley's recommendation) or pdfLaTeX, the `stix2` fonts,
  `lineno`, `adjustbox`, `placeins`, and Ghostscript (XeLaTeX converts the template's EPS logos
  with it). MiKTeX installs missing packages on first use; TeX Live users need
  `texlive-fonts-extra` for `stix2`.
- **Template fixes.** `paper/wileyNJD-Chicago.bst` is Wiley's file with small fixes marked
  `gmpe-bench fix`: duplicate function definitions removed (BibTeX errors), `,, and` in author
  lists, a stray ` .` after article titles, and DOIs printed (the shipped file ignored them).
  `lettersp.sty` is Wiley's `LETTERSP.STY` renamed to lower case so it is found on Linux and macOS.
- **Placeholders** to complete before submission: corresponding e-mail, funding,
  acknowledgments, the repository URL and Zenodo DOI in `references.bib` (`gmpebench2026`),
  and `\NTests` (the number of tests reported by `pytest -q`) in both `.tex` files.
